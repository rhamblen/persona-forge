# Persona Forge — session handover (2026-07-25)

**What it is:** self-hosted web app (GitHub `rhamblen/persona-forge`, deployed
`http://192.168.1.33:8890`) wrapping a ComfyUI character pipeline: Prompt Studio → Dataset
Builder → per-character LoRA → pose/expression sets → SillyTavern sprite export. Cold-start
brief: `docs/ai-context.md` (authoritative). Ship convention: finish → commit → tag → push →
GitHub release (never ask).

## Infra fix (permanent)
UR1 has two GPUs. Training was OOMing because the **RTX 3090** (ComfyUI) was shared with aux GPU
containers. **Fixed:** moved `ollama` + `chatterbox-st` to the idle **RTX 3060**; the 3090 now
has ~22 GB free. Gotchas: Unraid `get_gpu_metrics` **caches a stale 3090 value** — trust ComfyUI
`clear_vram` / `nvidia-smi` instead. Ollama on the 3060 needs `OLLAMA_MAX_LOADED_MODELS=1`
(confirm it was set). GPU UUIDs: 3060 `GPU-0471078b-…`, 3090 `GPU-266b3f71-…`. chatterbox GPU is
set in `/mnt/user/appdata/chatterbox-st/.env` (`NVIDIA_VISIBLE_DEVICES=nvidia.com/gpu=<uuid>`,
CDI form); ollama is an Unraid template container. See `project_comfyui_ur1_paths_and_env` memory.

## Open quality issue (the live thread) — the LoRA is weak & pose-locked
Test persona `sweetie-pie` (trigger `pf_sweetie_pie`, trained 500 steps in ~13m35s) came out
**weak, waist-up-biased, and can't do walking/waving/arms-crossed.** **Root cause (confirmed):**
the **Dataset Builder generates all candidates from the same prompt with only the seed varied**
(`dataset_generate` in `main.py` — `base = _version_prompt_params(version)` + fresh seed, no
pose/framing variation) — so the training set has zero pose diversity, the LoRA overfits identity
to one stance, and fights pose prompts. Same cause as the waist-up bias.

**Recipe for a good LoRA:** dataset with **pose + framing variety** (full-body, sitting, walking,
arms crossed, 3/4, side) + **~1500–2500 steps**. Quick levers to confirm/mitigate: LoRA strength
~0.5, or render with LoRA = None (the base model does the poses fine → proves the LoRA is the
limiter).

- LoRA-driven poses need `loras: /builds` in ComfyUI `extra_model_paths.yaml` (present) **+ a
  ComfyUI restart** after each new LoRA to see it — the `lora_build` job automates this restart.
- Manual **Train** / **Generate all** still work — the job engine reuses the same factored
